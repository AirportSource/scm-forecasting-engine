# Learning & Build Loop

This project follows a simple loop: learn only what is needed to move the project forward, then apply, test, and validate it before moving on.

```text
                    GITHUB PROJECT
                         |
                 prochaine tache
                         v
                 J'ESSAIE DE FAIRE
                         |
             +-----------+-----------+
             |                       |
        JE SAIS FAIRE           JE BLOQUE
             |                       |
             |                       v
             |               APPRENTISSAGE
             |                cours / doc
             |                       |
             |                       v
             |                   EXERCICE
             |                       |
             +-----------+-----------+
                         v
                        M5
                         |
                         v
                     TESTER
                         |
                         v
                      COMMIT
                         |
                         v
                   PREUVE OBTENUE
                         |
                         v
                       DONE
                         |
                         v
                prochaine tache
```

## Regle de fonctionnement

1. Choisir la prochaine tache utile dans le GitHub Project.
2. Essayer de la realiser avant d'ouvrir de nouvelles ressources.
3. Si je bloque, identifier precisement la notion manquante.
4. Apprendre cette notion avec une ressource ciblee.
5. Faire un petit exercice pour verifier la comprehension.
6. Revenir immediatement au projet M5.
7. Tester techniquement le resultat et verifier que je peux l'expliquer.
8. Faire un commit avec une description claire de ce qui a change.
9. Ne passer la tache en `Done` que lorsque la preuve attendue est obtenue.
10. Choisir ensuite la prochaine tache utile.

## Definition de "preuve obtenue"

Une tache n'est pas terminee uniquement parce que le code s'execute. Selon la tache, la preuve doit couvrir au moins une partie de ces trois dimensions :

- **Comprehension** : je peux expliquer ce que je fais et pourquoi.
- **Realisation** : le resultat fonctionne et peut etre reproduit.
- **Transfert** : je peux reutiliser la competence sur une variante, une autre serie ou un autre probleme.

## Principe d'apprentissage

La roadmap donne la direction, mais le planning reste court. Les connaissances sont consolidees par des rappels actifs, des exercices et surtout par leur reutilisation dans le projet.
